## 二、缺陷明细(按严重度)

### 中-1 无 # 深链丢失路由(任务方已实测复现,代码坐实)
- 位置:web/src/main.tsx:11(`<HashRouter>`);全库 grep `location.pathname|location.hash|window.location` 仅 App.tsx:99-103(沉浸模式判断)与 :106(回顶),**无任何路径→hash 的恢复逻辑**;server/src/app.ts:234-263(`sendIndex` 与 `app.get('/*')` SPA 兜底);deploy/nginx/app.conf.src(`/` 反代 api,兜底同源)。
- 问题:react-router-dom 6.28.0 的 HashRouter 只读 location.hash,URL path 部分被忽略。直接访问 `/textbook/english/en-u1-l1` → 应用壳加载后 hash 为空 → 按 `/` 渲染:未初始化设备落 OnboardingPage(App.tsx:116-122「跳回登录」),已初始化设备落 TodayPage(「跳回首页」)——与实测一致。
- 影响面:①外部路径链接(分享/收藏/二维码)全部丢失目标页;②两种既有部署(Render Fastify 同源托管、nginx→api)都有 SPA fallback,表现为**静默丢路由而非 404**,更难察觉;③若未来改为纯静态托管(无 fallback)则升级为 404;④应用内 `#/` 链接与站内刷新不受影响(hash 保留)。
- 修复方向(点到为止):入口处(index.html 内联脚本或 main.tsx 挂载前)检测 `location.pathname` 非根时搬移进 hash 再渲染;或整体切 BrowserRouter(服务端 fallback 已具备)。

### 中-2 LearnGate 文案/口径矛盾 + 不可达分支(行为与代码意图一致,不一致的是文案与逻辑)
- 位置:web/src/app/LearnGate.tsx:21(「家长登录后,才能开始学习。」)、:32 与 :35(主按钮分流与文案);web/src/app/AppProvider.tsx:819(`canLearn: state.onboarded`);对照提交 335dd45(「学习解锁不再依赖账号登录」)与 LoginBanner.tsx:26(「未登录家长账号:学习照常」)。
- 证据链:`canLearn = state.onboarded`——已初始化但未登录的设备**永不弹门禁、可直接学习**;门禁实际只出现在未完成引导的设备(新设备 / 访客模式)。对这些设备,解锁动作是「完成家长绑定 + 引导」,不是「登录」,文案误导。LearnGate.tsx:32,35 的 `state.onboarded ? '/settings' : '/onboarding'` 与「去登录」文案不可达:onboarded=true 时 canLearn=true、门禁根本不渲染——这是旧口径(学习需登录)残留的死分支。
- 影响:家长误以为孩子学习必须登录账号;访客设备上提示的动作与真实解锁路径不一致。
- 附:AppProvider.tsx:816-817 注释仍写「学习解锁必须同时满足『已登录』和『本机已初始化』」,与 819 行代码直接矛盾(同根因,另列低-5)。

## 三、仅记录(一行一条)

- localStorage 损坏不白屏:core/storage.ts:113-121(loadCachedState try/catch)+ core/model.ts `normalizeState` 逐字段校验,损坏 → 静默回初始 state;但无「检测到数据损坏」提示,未登录设备的本机进度会无感丢失(已登录设备可由云端恢复)。
- 家长 PIN 为单轮 SHA-256(salt:pin)(core/pin.ts:14-17):4 位空间 1 万,localStorage 一旦可读即可离线穷举;本机轻量门锁定位下可接受,可考虑 PBKDF2 慢哈希加固。
- crypto.subtle 仅 https/localhost 可用:自建 http 部署时 PIN 设置/校验必失败(CreatePinForm 有「设置失败」兜底);现有部署(Render、deploy/nginx 强制 https)不触发。
- LessonPage 未使用路由参数 :subject(LessonPage.tsx:33-35,lessonById 全局按 lessonId 查找):`/textbook/math/en-u1-l1` 也会渲染英语课;宽容不致错,做深链规范化时留意。
- 当前未提交 WIP(换账号 wipe 退出)小缺口:parentLogout('wipe') 清了 localStorage 数据与审计队列,但未清 pinUnlock 的 sessionStorage 键(core/pinSession.ts PIN_UNLOCK_KEY),清空后本标签页家长区仍处解锁态;需先有家长权限才可触发,风险低。

## 四、任务重点逐项核对小结

1. **深链**:成立,见中-1。影响面评估:既有两种部署均静默丢路由;应用内刷新不受影响;纯静态托管才会 404。
2. **LearnGate**:代码意图(路由级锁死+显式回首页)与实际行为一致;不一致的是文案/口径(中-2)与交互预期(低-1)。「每次导航都重现」源于门禁无状态且 canLearn 不变,是路由守卫的设计后果。
3. **AppProvider/存储初始化**:loadCachedState/loadDevice/readStoredAccount 均有 try/catch 与形态校验,损坏数据回退默认值,不会白屏;bootstrap 的 attemptRefresh/fetchRemote 全部捕获异常,ready 必然置位,无挂死路径。遗留:损坏无提示(仅记录)。
4. **错误边界**:不存在(全库 grep 无 ErrorBoundary/componentDidCatch/getDerivedStateFromError),main.tsx:8-18 裸渲染。任何渲染期异常 = 整树白屏且无恢复 UI。当前通读的页面代码均有参数/空值兜底,未发现具体触发向量,故未升「高」;建议补顶层 ErrorBoundary。
5. **路由表与守卫一致性**:/task、/lesson/{practice,dictation,words}、/mistake、/dictation/review、/sports 共 7 条学习路由全部包 LearnGate ✓;课本与 /lesson 详情不锁,符合「课本可随便看」口径 ✓;/report、/settings 内部 PinGate(含锁定/会话解锁/重置兜底)✓;无效 taskId/lessonId/questionId 均有 EmptyState 兜底,无崩溃 ✓。不一致点:中-2 死分支、低-3 focusRoute 缺 /sports、LearnGate「去登录」死分支。
