## 结论
发现 2 高 / 3 中 / 8 低（含仅记录）。高：①grade 切换把「删目标存档」放在 CAS 落库之前，CAS 失败即丢档；②登录限速器过期条目永不清理，公开端点可无界吃内存。中：grade 路由无限速（与自述注释矛盾）、trustProxy 缺失（反代下限速全局聚合）、双仓储 gradeArchives.upsert 的 createdAt 语义分叉。鉴权主链路（argon2id+JWT+轮换+复用检测+登出吊销）、CAS 状态同步、错误脱敏、归档只读约束实测全部通过。

## 高

### H1 grade 切换：删存档先于 CAS 落库，CAS 失败导致目标年级进度永久丢失
- 位置：server/src/services/gradeService.ts:151（restored=true）→ :159（删除 toKey 存档）→ :162-166（casUpdate）→ :170（CAS 未命中仅抛 409）。
- 问题：写序为「读 state → 封存 fromKey → 读 toKey 存档 → 恢复进 data → 删 toKey 存档 → CAS 落库」。存档删除不可回滚，且先于唯一的数据落库点；CAS 失败不回滚已删的档。
- 影响（真实场景）：docs/02 §3.2/D12 明确支持双设备并发。设备 A switch（恢复 g2s1 档）期间设备 B 任意 PUT 使 revision 前移 → A 的 CAS baseRevision 未命中 → 409，此时 toKey 档已删、恢复内容未落库。客户端随后重试 switch：findByKey(toKey)=null → 走「全新开始」分支，进度静默丢失且无任何报错。进程在删除与 CAS 间崩溃同理。这也直接回答②的「事务与幂等」：switch 全程无事务，恢复+删档两步不可回滚。
- 依据：gradeService.ts:159-170 原文写序；server/test/grade.test.ts 仅 happy path、无并发用例。
- 运行时验证：未复现——竞态窗口在内存仓储下为微秒级，外部 curl 无法确定性命中；本条依据代码写序证据，如实标注。
- 修复方向：将存档 delete 移到 casUpdate 成功之后；或 CAS 失败时补偿性回写 toKey 存档；Prisma 路径可在 repo 层加事务。

### H2 登录限速器过期窗口条目永不清理，公开端点可无界吃内存（DoS/OOM）
- 位置：server/src/lib/attemptLimiter.ts:28-34（isBlocked 对过期窗口返回 false 但不删除条目）、:36-45（recordFailure 为每个新 key 建条目）；app.ts:99-103 注入后无任何清理调用。
- 问题：windows Map 的 key = IP|username（routes/auth.ts:77）。爆破/扫描器轮换用户名即产生一次性 key，只有写入与覆盖，没有过期回收路径。
- 影响：部署形态为自托管常驻单机（docs/07/08/09；Render 免费档 512MB）。公网扫描器每秒数条随机用户名登录（每次 401、成本低，dummy argon2 hash 已缓存不放大），每天数十万条目，数日内可耗尽内存使进程 OOM——「不改动就会在真实场景出错」成立。
- 修复方向：isBlocked/recordFailure 命中过期条目时顺手删除该 key；或加周期清扫（时钟已可注入）。

## 中

### M1 grade 两条路由未挂限速，与路由注释自述矛盾
- 位置：server/src/routes/grade.ts:4（注释「限速沿用……30 次/分钟」）；:31-33（POST /grade/switch）与 :53（GET /grade-archives）均无 config.rateLimit。
- 运行时证据：2026-10-26 实测两接口响应均无 x-ratelimit-* 头；对照 /state PUT、/auth/refresh、/security-events POST 均带限速头。@fastify/rate-limit 注册为 global:false（app.ts:113-117），未声明即完全不限速。
- 影响：登录用户可无限调用 switch（每次含多次仓储写与历史槽写）；同时违反 docs/03 §8.4-3「每个路由上线前必须回答要不要限速」的结论要求（注释声称有、实现没有）。
- 修复方向：按注释补 30 次/分钟、键=accountId 的窗口。

### M2 app.ts 未配置 trustProxy，反代部署下按 IP 限速全局聚合
- 位置：server/src/app.ts:135 `const app = Fastify({ logger })`，无 trustProxy。
- 依据：docs/07:301（§3.4-1）明确要求「api 必须以 trustProxy 信任内网一跳，否则按 IP 限速全家误伤、按 IP+username 限速全局误锁」；docs/07:347（A7 验收）要求核对；render.yaml 与 deploy/nginx 均为反代形态。
- 影响：上线后 request.ip 恒为代理 IP → register 3 次/小时、refresh 30 次/分钟、登录限速键中的 IP 全部退化为全局共享配额，全站用户互相误锁。
- 修复方向：Fastify 选项加 trustProxy（按部署拓扑定跳数），再核对四类按 IP 限速键。

### M3 双仓储 gradeArchives.upsert 的 createdAt 语义分叉（同接口两实现不一致）
- 位置：server/src/repos/memory.ts:130-141（覆写时 createdAt=input.now，每次封存刷新时间）vs server/src/repos/prisma.ts:146-150（update 分支仅更新 snapshot/summary，保留首次 createdAt）。
- 影响：listByFamily 按 createdAt desc 排序（memory.ts:143-145 / prisma.ts:154-156），createdAt 直接外显（gradeService.ts:32-40）→ 重复封存同一年级后，本地/测试（内存）与生产（Prisma）的列表顺序与显示时间不同：测试通过不等于生产行为。
- 修复方向：定死语义（建议「首次封存时间」= Prisma 现状），memory 侧对齐。

## 实测通过项（对应六个审查重点）
1. 鉴权链路：argon2id 参数符合 OWASP 下限档（lib/argon2.ts:8-14，19MiB/t=2/p=1）；refresh 原文只存 SHA-256（lib/tokens.ts）；未知用户名做等价 argon2 校验防时序侧信道（authService.ts:41-47）；JWT claims 带 typ 防混用（lib/jwt.ts）；轮换+复用检测+全量吊销+refresh-reuse 留痕实测通过；登出实测服务端吊销（登出后同 cookie 刷新 401）；无 cookie 刷新 401 且清 cookie。cookie 属性四件套实测正确（见 L1 的环境注意项）。
2. 状态 CAS：惰性首写 revision=1、stale baseRevision → 409 且响应附 data/revision/updatedAt、CAS 命中 → 200 并 bump、RISK-01（云端有非空 archive 而请求缺字段 → 400 archive_wiped；显式空 archive {} 放行）实测全部符合 docs/02 §3.2；环形历史 5 槽按 revision 降序正确；PUT 限速 60/分钟/账号（键=principal.sub）。
3. 限速覆盖：register 3/h/IP（实测头 x-ratelimit-limit:3）、login 5/15min（实测第 6 次 429 rate_limited）、refresh+logout 30/min/IP、security-events POST 10/min/账号；缺的是 grade 两路由（见 M1）。
4. 双仓储差异：除 M3（gradeArchives.createdAt）与 L8 两条无害差异外，refreshTokens/state/accounts 的方法语义逐一对齐（revokeIfActive、insertFirst 撞唯一键回读、deleteExpiredBefore 的 lt 边界一致）。
5. 错误与日志：pino redact 覆盖 authorization/cookie/set-cookie（app.ts:57-60）；错误响应一律固定中文短句，zod 细节仅 debug 日志（auth.ts:30、state.ts:70 等）；仓储异常统一 503 不漏细节（repoCall.ts）；health 不泄漏拓扑；404/405/413/415/400 实测码与响应体均符合契约。
6. grade 归档只读：GET /grade-archives 无副作用（实测），不存在直改/直删存档的路由，删除只发生在 switch 恢复流程内（见 H1 的写序问题）；bad fromKey → 400。
