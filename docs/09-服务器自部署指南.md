# 09 · 服务器自部署指南（前后端同机 · 公网访问 · 数据安全）

- **角色**：部署运维（2026-10-25 落地，配套 `deploy/` 部署包）
- **形态**：单台服务器 Docker Compose——`nginx`（TLS 终结与边缘）→ `api`（Fastify，同源托管前端静态文件）→ `postgres`（仅容器内网，不出公网）。前端与后端**同机同源**部署，公网通过 `https://你的域名` 访问。
- **与 docs/08 的关系**：08 是 Render+Neon 免费托管方案；本文是你自有服务器（含 Oracle 永久免费 VM、公司/学校服务器）的完整方案。二选一即可。

## 一、前提清单

| 项 | 要求 | 说明 |
|---|---|---|
| 服务器 | Ubuntu 22.04+/Debian 12，1 核 1G 起（2G 更从容），能出公网 | Oracle Always Free / 任何 VPS 均可 |
| 域名 | 一个域名，A 记录指向服务器公网 IP | TLS 必需；无域名见 §7 备选 |
| Docker | 已装 Docker Engine + Compose v2 | `curl -fsSL https://get.docker.com \| sh` |
| 端口 | 80/443 对公网开放，22 仅限你的 IP | 见 §5 防火墙 |

## 二、十分钟部署

```bash
# 1) 拿代码
git clone <你的仓库地址> /opt/xiaotao && cd /opt/xiaotao/deploy

# 2) 配置：先填域名与邮箱，再一键生成强随机密钥
cp .env.example .env && vim .env      # 填 DOMAIN=、ACME_EMAIL=
bash gen-secrets.sh                   # 生成数据库密码/JWT/备份密钥

# 3) 一键上云：签发证书 → 起全栈 → 建表 → 自检
bash init-https.sh
```

日常命令：`docker compose up -d --build`（更新）、`docker compose logs -f api`（日志）、`docker compose down`（停机，数据卷保留）。

## 三、拓扑与信任边界

```
公网 ──443(TLS)──> nginx(边缘：HSTS/限体积/gzip)
                     │ 内网 edge
                     ▼
                  api(Fastify: 鉴权/CAS/限速/同源静态)
                     │ 内网 internal
                     ▼
                  postgres(不映射端口，公网不可达)
```

- PostgreSQL **不发布任何端口**，只在 compose 内网 `internal` 中可达。
- 静态文件与 `/api` 同域：refresh cookie（`HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth`）完整生效。
- 证书自动续期：certbot 容器每 12h 检查，nginx 每 6h reload。

## 四、数据安全（本方案的设计要点）

### 4.1 传输安全
- 全站强制 HTTPS（80 → 301 → 443），TLS 1.2/1.3；HSTS 6 个月；安全响应头（nosniff/DENY/Referrer-Policy/Permissions-Policy）在 nginx 层加。
- 状态接口 `cache-control: no-store`，学习数据不落任何中间缓存。

### 4.2 存储安全
- 数据只存在本机 Docker 卷 `pgdata`；不使用任何第三方云数据库。
- 静态加密建议（可选增强）：云厂商云盘加密，或自建 LUKS 全盘加密后挂载 `/var/lib/docker`。
- 密钥文件 `.env`（数据库密码/JWT）与 `backup.key` 均 `chmod 600`、已被 .gitignore/.dockerignore 排除，**绝不入仓库与镜像**。

### 4.3 备份与容灾（防丢失是数据安全的另一半）
- **每日自动备份**：`backup.sh` → `pg_dump → gzip → AES-256 加密 → backups/`（保留 14 份）。crontab：`30 3 * * * /opt/xiaotao/deploy/backup.sh`。
- **异地容灾**：`backups/` + `backup.key` 副本同步到家用 NAS/网盘（rclone 一行命令；`backup.key` 与备份分开存放更稳）。
- **应用层双保险**（代码已内置）：`family_state_history` 环形 5 版可在线回退；家长应用内每周日导出 JSON。
- **季度演练**：在测试机上跑 `restore.sh` 恢复一份备份并核对 `/api/v1/health` 与登录。

### 4.4 访问安全
- 应用层（已内置）：argon2id、JWT 2h + refresh 30 天轮换与复用全吊销、登录限速 5 次/15 分钟、写接口限速、审计事件（PIN 重置/凭证复用）上云留痕。
- 服务器层（首次部署执行一次，见 §5）：防火墙仅开 80/443/SSH、SSH 密钥登录、fail2ban 可选、`docker compose pull && up -d --build` 每月安全更新。

### 4.5 隐私与合规边界
- 只存孩子昵称与学习记录；不采姓名/学校/位置/设备标识（沿袭 v1 边界）。
- 未成年数据：应用内隐私说明页 + 家长知情确认（P0 前端功能，事件写入 `security_events` 留痕）。

## 五、首次部署安全加固清单（一次性）

```bash
# 防火墙（Ubuntu ufw）
ufw default deny incoming && ufw allow 80/tcp && ufw allow 443/tcp
ufw allow from <你的IP> to any port 22 proto tcp && ufw enable

# SSH：禁密码、禁 root
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/;s/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config && systemctl restart ssh

# 可选：fail2ban（防爆破）
apt install -y fail2ban && systemctl enable --now fail2ban
```

## 六、部署后验收清单

- [ ] `https://域名/api/v1/health` → `{"ok":true,...}`
- [ ] `http://域名` 30 跳 `https`；浏览器证书锁正常、无混合内容
- [ ] 注册→登录→刷新页面仍登录（cookie `Secure; SameSite=Strict` 在同源生效）
- [ ] 第二台设备同账号 `GET /api/v1/state` 能读到第一台写入的数据
- [ ] 手机浏览器可安装到主屏（PWA manifest 正常返回）
- [ ] `bash backup.sh` 产出加密文件；`ls backups/` 可见
- [ ] `docker compose ps` 四个服务全部 healthy/running；`docker compose exec db psql -U xiaotao -c '\dt'` 六张表在

## 七、没有域名时的备选

1. **Cloudflare 免费域名 + Tunnel**（推荐）：域名托管到 Cloudflare（免费），服务器装 cloudflared 隧道，无需公网开 80/443，TLS 由 Cloudflare 终结——nginx 层可省。
2. **纯 IP + 自签证书**：仅家庭临时体验（浏览器告警需手动信任），不建议给孩子日常用。

## 八、故障排查

| 症状 | 处置 |
|---|---|
| init-https.sh 卡在申请证书 | DNS 未生效/80 不通：`dig 域名` 核对 A 记录；云厂商安全组放行 80 |
| api 起不来，日志 `JWT_SECRET 长度` | 重跑 `bash gen-secrets.sh` 后 `docker compose up -d` |
| 502 | `docker compose logs api`；常见为迁移未跑：`docker compose run --rm api npx prisma migrate deploy` |
| 忘记备份密钥 | 旧备份不可解密（这是加密的意义）；生成新 key 走新备份 |
