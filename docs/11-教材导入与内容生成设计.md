# 11 · 教材导入与内容生成 — 设计方案（v1，待评审）

- **角色**：产品经理 + 架构师（2026-10-25）
- **性质**：设计方案，**不含实现**。评审通过后按 §八 排期进入开发。
- **输入依据**：用户需求「新学习开始，家长可以导入对应的学习教材，生成教学内容」；现有代码 `web/src/data/content/`（硬编码三科内容）、`docs/02-技术架构方案.md` §5（contentVersion 迁移，本方案是其落地载体）、`docs/01` 开放问题 Q1（换教材时旧学习数据处置）。
- **目标设备**：第一期仍以 Redmi Pad Pro 为主（家长操作可在任意浏览器完成）。

---

## 一、要解决的问题

1. **学期悬崖**（docs/00 风险台账第 1 条）：三科内容硬编码在源码里，二上学期结束产品即失效；换二下教材需要开发者重新写内容、发版。
2. **内容与数据强耦合**：换教材 = 课/题 id 全变（英语换版已发生过一次），错题本、掌握度悬空——`contentVersion` 迁移机制（P0）一直没有落地载体。
3. **校对成本错配**：README 要求家长「直接改 `src/data/content/english.ts`」——把家长当开发者。
4. **多家庭差异化**：有的孩子用北师大版、有的进度不同——单一内置内容无法覆盖。

**一句话方案**：家长以拍照/粘贴等方式提供教材材料，系统（AI 辅助）生成结构化「内容包」，**经家长逐项审核后启用**；内容包作为一等数据存服务端并参与版本化迁移，现有计划/判分/进度/周报全部无感复用。

## 二、核心概念与架构决策

### ADR-002：内容包（Content Package）成为一等数据

**决策**：把「教材内容」从源码常量升级为可存储、可版本化、可切换的数据实体；**内容本体不进 `family_state`**（规避 256KB 上限，独立接口分发）。

```
                    ┌─ 内置包 builtin-v1（现三科内容原样平移，随代码发布，只读）
内容提供层 ─────────┤
                    └─ 导入包 pkg_<id>（家长导入生成，存 content_packages 表，可多包并存）

web/src/data/content/index.ts 改造为「内容注册表」：
  内容消费方（plan.ts / grading / progress / pages）接口签名不变，
  按 state.activePackage 解析到内置包或拉取缓存的导入包。
  ⇒ core/ 全部纯函数（计划生成、判分、SRS、宠物）零改动 —— 本方案最重要的复用点。
```

### 服务端存储（新增一表，走既有 Prisma 迁移）

```prisma
model ContentPackage {
  id          String   @id                    // pkg_<cuid>
  familyId    String   @map("family_id")
  subject     String                          // chinese / math / english
  title       String                          // 「人教版二年级下册 · 数学」
  contentVersion String @map("content_version") // semver：包内内容变更即升
  status      String                          // draft / reviewing / active / archived（archived 可重新激活，永不自动删除）
  data        Json                            // 完整内容包（§三 schema）
  learningArchive Json? @map("learning_archive") // ADR-003：切走时冻结的学习记录快照（lessons/mistakes/weakness/dictationQueue 及摘要）
  aiMeta      Json?  @map("ai_meta")          // 生成来源、模型、引文清单（审计用）
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")
  @@index([familyId, subject])
}
```

### ADR-003：学期归档——换教材「只封存，不删除」（用户决策 2026-10-25）

**决策**：更新教材时，历史教材包与历史学习记录**永久保留**，三层语义：

1. **教材包保留**：`active → archived` 只是状态切换；归档包可随时在「教材与内容」页查看全部课目与题目，**可重新激活**（P3 复习旧教材场景）。
2. **学习记录冻结**：激活新包时，服务端把旧包关联的学习切片（`lessons` 掌握度、`mistakes`、`weakness`、`dictationQueue` 及完成度摘要）快照进该包的 `learningArchive`，随后从活动 state 移除（保持 family_state 轻量，配合 P0 归档策略）；日期键的 `dailyLogs/freeLogs` 天然是历史，留在 state 不动。
3. **情感资产永续**：星星、桃粮、大餐、连续天数、徽章、宠物**跨学期不清空**——换教材是「开学」，不是「重新做人」。

**家长可见性**：记录页与周报页顶部新增「学期」选择器（当前学期 / 历史学期列表）；历史学期视图只读展示当时的内容目录、掌握度汇总、错题本，并可导出该学期 JSON。**切回旧包时二选一**：恢复存档（接续当年进度与错题）或全新开始（存档继续保留）。删除仅限草稿；归档包的删除需先导出且二次确认（默认路径不存在删除）。

**服务端语义**：activate 请求携带 `{newPackageId, oldPackageHandling: 'archive'}`（唯一支持值；`archive` 内部完成快照+移除，事务化）。

**API 契约新增**（沿用 docs/02 错误码与鉴权惯例）：
- `GET /api/v1/content/packages` — 列表（含 status）
- `POST /api/v1/content/packages` — 创建草稿（导入原始材料 → 服务端调 AI 生成 → 存 draft）
- `PATCH /api/v1/content/packages/:id` — 家长审核修改（逐题采用/编辑/弃用）
- `POST /api/v1/content/packages/:id/activate` — 激活（触发 state.contentVersion 迁移链）
- `GET /api/v1/content/packages/:id/data` — 内容本体（ETag 缓存，设备离线可用）
- `DELETE /api/v1/content/packages/:id` — 仅 archived 可删
- AI 调用密钥：`PATCH /api/v1/settings/ai`（key 服务端存储，**绝不下发前端**，日志脱敏沿用现有 REDACT 红线）

### 数据形态：完全复用现有类型

导入包的 `data` 就是现有 `src/data/types.ts` 的 `Unit[] + Lesson[]`（含 Question/DictationWord/EnglishWord），由 `builders.ts` 的 seed 规范生成。**这是设计上的刻意选择**：换教材不改任何消费方代码；`tests/englishContent.test.ts` 的「内容钉死」模式转作包级 lint。

## 三、生成流水线（Import → Generate → Review → Activate）

```
[输入材料] ──▶ [结构提取] ──▶ [内容生成] ──▶ [校验层] ──▶ [家长审核] ──▶ [激活切换]
 拍照/粘贴       单元/课骨架      知识卡+题目      schema+lint     逐题三选一      contentVersion
 手动建骨架      （低风险）       （高风险）        +引文对照        强制闸门         迁移链接管
```

### 3.1 输入方式（第一期排序）

| 方式 | 材料 | 风险 | 期数 |
|---|---|---|---|
| ① 文本粘贴 | 家长从教辅/课本电子版复制单元课文与生字表 | 低 | **P1（MVP）** |
| ② 手动建骨架 | 家长按向导填「单元→课→标题」，题目由 AI 按课题名生成 | 低 | P1 |
| ③ 拍照识别 | 课本目录页/单元首页照片 → AI 视觉提取 | 中（需隐私说明，见 §六） | P2 |
| ④ ISBN/教材名检索 | 自动匹配公开教材目录 | 中（覆盖率与版权不确定） | P3 |

### 3.2 AI 服务设计（关键决策：BYO Key + 服务端代理）

- **模型**：家长在设置页自备 API Key（推荐国产低价模型：DeepSeek / GLM / 通义；国内直连、生成一册成本约 0.5–2 元）。服务端只做代理与编排，**不内置任何平台密钥**——家庭自用产品不背 AI 成本，也避免密钥分发风险。
- **调用编排**（server 新增 `contentGenService`）：
  1. **结构生成**（1 次调用）：输入材料 → 输出单元/课树（标题、序号、每课 preview/review 知识点）；约束：只依据材料，不臆造课数。
  2. **逐课题目生成**（每课 1 次调用）：输入该课知识点 + 材料原文引文 → 输出 3–8 题五题型（choice/truefalse/match/order/numeric）+ 听写词（语文：字词+拼音）+ 口算档位标记（沿用 `oralStageForLesson` 课序规则，防超纲）。
  3. **引文要求**：每题必须附 `sourceQuote`（材料原文片段）——家长审核时对照有抓手，这是防幻觉的核心手段。
- **失败与降级**：AI 不可用/额度用尽 → 向导提示，纯手动模式全程可用（结构手填、题目手写，草稿保存不依赖 AI）。

### 3.3 校验层（自动，生成后立即执行）

1. **Schema 校验**：按 builders 类型全量验证（题型字段完整性、答案索引在范围内、拼音声调格式、英语单词字段齐备）。
2. **内容 lint**：题干非空且 ≤80 字；选项 ≥2 且不重复；match 左右数量一致；口算题数值域符合二上/二下规则（复用 `tests/oralMath.test.ts` 的断言）；每课 ≥2 题、听写词拼音去重。
3. **适龄约束**（注入生成 prompt + lint 双保险）：不出现超纲概念（如二上不出现除法/乘法竖式）、题干识字量 ≤ 二年级、答案唯一确定。
4. lint 不合格的条目标黄进审核队列，不阻断整包。

### 3.4 家长审核（强制闸门，产品红线）

- **draft → reviewing → active** 状态机；`active` 必须经过审核页确认。
- 审核页（家长区，移动优先）：按课分组，每条内容三选一——**采用 / 编辑 / 弃用**；题干旁并列展示 `sourceQuote` 原文；整体进度条（已审 N/M）。
- 与儿童侧隔离：审核完成前孩子端完全不可见导入包；审核中可随时保存离开（沿用 LeaveConfirmDialog 惯例）。
- 激活前二次确认弹窗：展示「本包 N 单元 M 课 K 题，启用后三科指针将重置为第 1 课」。

### 3.5 激活与数据迁移（ADR-003 归档语义）

- `state.activePackages[subject] = packageId + contentVersion`（SyncState 新增字段，normalizeState 兼容旧数据缺省 = builtin）。
- 激活即触发 **docs/02 §5 的迁移链**，但语义按 ADR-003 调整为**归档而非迁移/清除**：
  - 旧包关联的学习切片整体冻结进 `learningArchive`（错题、掌握度、薄弱点、听写队列原样保留）；
  - 新学期从新教材第 1 课开始（三科指针重置），历史在「学期选择器」中随时可查；
  - **不再需要**家长在「迁移 or 清除」间做选择——原 docs/01 开放问题 Q1 / 本文档 Q4 就此关闭。
- 内置包（builtin-v1）同样适用归档语义：第一次激活导入包时，内置三科的学习记录冻结进 builtin 包的归档。
- 切换记录写 `security_events`（type: `content-switch`），含新旧包 id 与快照摘要。

## 四、产品形态（页面与流程）

家长区新增「教材与内容」卡（设置页 rail）→ 向导三步：

1. **选科目与方式**（粘贴 / 骨架 / 拍照(P2)）
2. **材料确认**（结构树预览，可增删课）→ 生成进度（逐课，可暂停）
3. **审核**（3.4）→ 激活（激活确认文案：「上一册教材与学习记录将完整封存，可在记录页随时查看」）

孩子侧唯一变化：课本页目录来自当前激活包；「内置 / 已导入」在课本页右上以小徽标区分。

**历史学期入口**（ADR-003 配套）：记录页与周报页顶部学期选择器——当前学期默认展示；历史学期列表（如「二年级上册 · 数学（已封存）」）进入后只读：内容目录、掌握度汇总、错题本、导出该学期 JSON。重新激活入口也在历史学期详情页（恢复存档 / 全新开始 二选一）。

**量级预估**：一册语文（8 单元 28 课）生成 ≈ 30 次 LLM 调用、审核约 30–60 分钟（家长分段完成）；ByoKey 成本约 1 元内。归档快照单次约 30–80KB（存服务端，不占 family_state）。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| AI 幻觉产生错误知识 | 强制引文对照 + 家长审核闸门 + 审核页「与课本对照」提示常驻 |
| 内容包撞大（单册可能 >256KB） | 内容本体走独立接口+ETag，不进 family_state（架构性规避） |
| 版权与隐私 | 定位「家庭自用、家长自备材料」；拍照功能上线前隐私页明确「照片发送至您配置的模型服务商」；不提供包分享功能（P3 如做，仅分享家长手写部分） |
| 家长审核负担 | 分课审核可分段；引文并列降低核对成本；lint 先过滤明显问题 |
| 多设备一致性 | activePackages 进 state 走既有 CAS 同步；包本体 ETag 缓存 |
| 中文 token 成本失控 | 逐课生成 + 家长手动确认后才生成下一课；硬性单包调用上限 |

## 八、排期建议（评审通过后）

| 阶段 | 内容 | 前置 |
|---|---|---|
| P1-MVP | 服务端包存储+API（含 ADR-003 归档快照事务）、粘贴/骨架向导、逐课生成、校验层、审核页、激活切换、contentVersion 迁移落地、**历史学期选择器（只读视图 + 导出）** | 建议先完成 docs/02 已排期的 P0 归档与内容版本设计评审 |
| P2 | 拍照视觉提取、听写词/英语内容生成、多包管理页、**重新激活（恢复存档/全新开始）** | P1 稳定运行 |
| P3 | ISBN 检索、内容包导出/导入（JSON）、包分享（仅家长手写内容） | 视需求 |
