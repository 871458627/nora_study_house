# 08 · 免费部署指南（Render + Neon）

- **角色**：部署运维（方案评估与落地适配由本团队完成，2026-10-25）
- **结论**：选定 **Render 免费 Web Service（跑 API + 同源托管前端）+ Neon 免费 PostgreSQL**。这是同时满足本项目两个硬约束的唯一真免费组合：
  1. **必须同源**——refresh cookie 为 `SameSite=Strict; Path=/api/v1/auth`，前后端分域会导致 cookie 拒发、登录态失效。已由 Fastify 直接托管 `web/dist` 解决（`WEB_DIST_DIR`）。
  2. **必须常驻进程**——登录限速器与 @fastify/rate-limit 状态在进程内存。因此 Vercel/Netlify serverless 不可用。
- **备选**：Oracle Cloud 永久免费 ARM VM 按 `docs/07` 的 Docker 方案一台机全跑（不休眠，但注册要信用卡、容量看运气）；`docs/07` 完整生产方案（备份/监控/回滚）继续有效。

## 一、额度核对（单家庭用量 << 免费额度）

| 资源 | 免费额度 | 本项目预估 |
|---|---|---|
| Render 实例 | 750 实例小时/月，512MB RAM | 744 小时/月（单服务全天），刚好覆盖 |
| Render 休眠 | 15 分钟无流量休眠，冷启动 30–60s | 家庭早晚各同步一次，影响极小；介意可用 cron-job.org 每 10 分钟 ping `/api/v1/health` 保活 |
| Neon 存储 | 0.5GB | 全量数据 <10MB |
| Neon 计算 | 100 CU·时/月，闲置 5 分钟自动挂起（唤醒 <1s） | 每天几十次请求，用量 <1% |
| 带宽 | Render 约 5GB/月 | 前端包 <1MB，远够 |

注意：**不要用 Render 自带免费 Postgres（30 天删除）**，数据库一律放 Neon。

## 二、部署步骤（从零开始，约 25 分钟）

### 0. 推代码到 GitHub（约 5 分钟，一次性）

1. 注册/登录 <https://github.com> → 右上角 **+ → New repository**：
   - Repository name：`xiaotao`；选 **Private**；其余默认 → **Create repository**。
2. 在本机项目目录执行（把 `<你的用户名>` 换成你的 GitHub 用户名）：

   ```bash
   cd /d/ai_projects/zcode_peoject/taotaolearning
   git remote add origin https://github.com/<你的用户名>/xiaotao.git
   git push -u origin main
   ```

3. 首次 push 会弹出 GitHub 登录窗口（Git Credential Manager），浏览器授权一次即可。之后每次 `git push`，Render 会自动重新部署。

### 1. 建 Neon 数据库（约 5 分钟）

1. 打开 <https://neon.tech> → **Sign up with GitHub**。
2. **Create project**：名称 `xiaotao`，Region 选 **Singapore (ap-southeast-1)** → Create。
3. 项目页 **Connection Details** → 复制完整连接串（形如
   `postgresql://user:pass@ep-xxx.aws-singapore-1.aws.neon.tech/neondb?sslmode=require`）。
   建议在串尾追加 `&connection_limit=5`（Prisma 连接池收敛，免费档更稳）。

### 2. Render 部署（约 10 分钟，其中构建 5-8 分钟）

1. 打开 <https://render.com> → **Get Started** → 用 GitHub 账号登录并授权（Install & Authorize 时可选择 Only select repositories → 勾选 `xiaotao`）。
2. Dashboard → **New + → Blueprint** → 选中 `xiaotao` 仓库 → **Apply**（识别根目录 `render.yaml`）。
3. 弹出两次 `DATABASE_URL` 输入（web 服务一次、xiaotao-migrate Job 一次）——**两次都粘贴同一条 Neon 连接串** → 继续 Apply。
4. 等待 `xiaotao-app` 构建完成变 **Live**，得到地址 `https://xiaotao-app.onrender.com`（名字冲突时 Render 会自动加后缀，以控制台显示为准）。

### 3. 建表（约 1 分钟）

Dashboard → 左侧 **Jobs → xiaotao-migrate → 右上角 Run** → 等状态变 Succeeded（日志应显示
`prisma migrate deploy` 应用了 1 个 migration、六张表）。

### 4. 验证与首次使用

1. 浏览器打开 `https://<你的地址>.onrender.com/api/v1/health` → 应返回 `{"ok":true,...}`。
2. 打开根地址 → 出现前端页面；注册家长账号（用户名 3-32 位字母数字，密码 ≥8 位）。
3. 手机浏览器打开同一地址 → 登录同一账号 → 「添加到主屏幕」即成为孩子设备入口。

### 5. 常见卡点

| 现象 | 处置 |
|---|---|
| push 提示鉴权失败 | 重试让 Credential Manager 弹窗登录；或 GitHub → Settings → Developer settings → PAT 生成 token，推送时当密码用 |
| Blueprint 找不到仓库 | Render → Account Settings → Applications 里给 Render 重新授权该仓库 |
| 构建失败：`npm ci` 报 lock 不一致 | 本地分别在 web/、server/ 提交最新 package-lock.json 再 push |
| `/api/v1/health` 503 | 大概率没跑 migrate Job，或 Neon 连接串漏了 `sslmode=require` |
| 首次打开 30-60 秒无响应 | 免费档休眠唤醒，属正常；常驻可配 cron-job.org 每 10 分钟 GET health |

## 三、环境变量清单（render.yaml 已固化，仅需人工填 DATABASE_URL）

| 变量 | 值 | 说明 |
|---|---|---|
| `DATABASE_URL` | Neon 连接串（**sync:false，控制台输入**） | 两个服务都要填 |
| `JWT_SECRET` | Render `generateValue: true` 自动生成 ≥32 字节 | 轮换会使所有 access/refresh 失效，需提前通知 |
| `XTAO_REPO` | `prisma` | 内存仓储仅限本地 |
| `WEB_DIST_DIR` | `../web/dist` | 相对 server 启动目录 |
| `HOST` | `0.0.0.0` | 容器内必须 |

## 四、运维要点（免费档特有）

- **冷启动**：休眠后首次请求慢 30–60 秒。PWA + localStorage 缓存使离线体验不受影响；保活见上表。
- **迁移**：schema 变更 → 新增 migration 目录 → 推送后在 Render 控制台 Run `xiaotao-migrate` Job。
- **备份**：云端 `family_state_history` 环形 5 版 + 每周日家长应用内导出 JSON（docs/07 双路恢复不变）。
- **额度耗尽表现**：750 小时用尽（几乎不可能，单服务 744h）→ 服务停到月底；Neon 超存储 → 拒绝写入，注意归档机制（P0 状态归档）控制体积。
- **密钥红线**：Neon 连接串与 JWT_SECRET 只存 Render 环境变量，绝不入仓库；`.env` 已被 .gitignore 排除。
