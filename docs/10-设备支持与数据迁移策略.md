# 10 · 设备支持与数据迁移策略（第一期 Redmi Pad Pro）

- **角色**：产品经理 + 架构师（2026-10-25）
- **口径**：第一期交付目标只有一台 **Redmi Pad Pro**（小米平板，11.2" / 2880×1800 / HyperOS，浏览器以 Chrome 系为准）；电脑、平板、手机三端访问与数据迁移为**预留能力**，不在第一期验收范围，但架构与部署不得为其设置障碍。

## 一、为什么当前架构天然支持"单设备先行、多端预留"

| 预留能力 | 架构现状 | 第一期在 Redmi Pad Pro 上的表现 |
|---|---|---|
| 多端同账号访问 | 账号体系（JWT + refresh）+ 云端单状态 CAS 同步（`GET/PUT /api/v1/state`） | 单设备也走完整链路：登录 → 本地缓存 → 防抖推送；第二台设备出现时**零改造**，登录同账号即可 |
| 设备无关性 | 设备态（PIN 哈希/修订号/dirty）存 localStorage，业务态云端一份 | 换任何浏览器/设备，登录即恢复全部学习数据 |
| 离线优先 | localStorage 全量缓存，断网可学，恢复后补推（dirty 优先策略） | 平板在家的 Wi-Fi 场景天然覆盖；断网写、联网推 |
| 数据迁移 | 见 §3 迁移矩阵（五条路径全部已有机制支撑） | 第一期实际会用到的：JSON 导出/导入 + 云端历史 |

UI 层多端适配同样是现成的：应用为响应式设计，断点 1080/920/720/430——手机（≤920 底部五标签）、平板/桌面（>920 顶部导航 + 双栏）。平板竖屏落在双栏形态、横屏接近桌面形态，无需为 Pad 单独开发。

## 二、Redmi Pad Pro 首验清单（设备到手后逐项过，问题回填给前端会话）

**环境**：Chrome（或小米浏览器，以 Chrome 为准）访问 `https://<部署地址>`。

| # | 验证项 | 通过标准 | 风险点 |
|---|---|---|---|
| 1 | 布局 | 竖屏、横屏均无横向滚动、无元素截断；答题专注模式隐藏导航 | 2880 宽屏下字号/间距观感需人工确认 |
| 2 | 触控 | 选项、按钮、读题喇叭（P1 上线后）点按灵敏；无 300ms 延迟感 | — |
| 3 | 登录态 | 登录后关浏览器重开仍是登录态（refresh cookie 生效） | 小米浏览器对 SameSite=Strict 的兼容性；异常则改用 Chrome |
| 4 | **TTS 听写朗读** | 听写页能出声读词；设置开/关 TTS 生效 | **P0 未闭环项**：Android SpeechSynthesis 中文音色与手势触发限制；失败时应用会降级拼音显示，需确认降级文案可见 |
| 5 | PWA 安装 | Chrome 菜单「安装应用/添加到主屏幕」→ 全屏无地址栏启动 | HyperOS 默认浏览器可能不给安装入口，务必用 Chrome |
| 6 | 离线打开 | 首次访问后开飞行模式再打开应用：能进页面、能做题（联网后自动补推） | **依赖前端补 Service Worker**（见 §4-1），未加前此项预期不过 |
| 7 | 输入法 | 听写"听音写字"模式调出键盘、数字题输入正常 | 平板外接键盘场景顺带看一眼 |
| 8 | 性能 | 页面切换流畅，无白屏超过 1s | 免费托管冷启动首开 30-60s 属正常（docs/08） |

清单 4、6 是真正的 P0 缺口，已在风险台账（docs/00 §五）对应条目下补充设备维度。

## 三、数据迁移矩阵（五条路径，第一期即可用/已预留）

| 路径 | 机制 | 状态 |
|---|---|---|
| ① 设备间迁移（换平板/加手机） | 新设备登录同账号 → 拉取云端状态；旧设备数据仍在本地缓存不丢失 | ✅ 已实现（后端 65 例覆盖） |
| ② 手动备份迁移（无云场景） | 设置页导出 JSON → 任意设备导入（带预览确认，docs/01 FR-P0 相关） | ✅ 前端已有导入链路；审计留痕走 `security-events` |
| ③ 误操作恢复 | 云端 `family_state_history` 环形 5 版（`GET /api/v1/state/history`）+ ② 的 JSON | ✅ 已实现 |
| ④ 教材内容升级 | `contentVersion` + 内容 id 迁移（换教材不清学习记录） | 🔜 P0 前端任务（docs/02 §5.2） |
| ⑤ **托管平台迁移**（Render+Neon → 自有服务器等） | `pg_dump`（或 Neon 控制台导出）→ 新环境 `restore.sh`/`prisma migrate deploy` → 前端无感知切域名 | ✅ docs/08↔docs/09 互迁路径已打通（部署形态差异仅在运维层） |

## 四、给前端会话的适配需求单（不在本会话实现）

1. **Service Worker（PWA 离线打开，Pad 常驻使用的体验关键）**：缓存应用壳 + assets（内容哈希长缓存已就绪），`/api/*` 永不缓存（no-store 语义）；建议 Vite PWA 插件生成，registry 与docs/05 动效规范无冲突。
2. **平板断点观感走查**：按 §2-1 在 960/1200/1600 CSS px 三档确认双栏与字号（设计基准 05 号规范 §1.7）。
3. **TTS Android 兼容**：`useSpeech` 在 Android Chrome 的音色选择与首次手势触发；降级拼音的提示可见性。
4. manifest 已就绪（横竖屏 icon、display standalone），补充 `theme_color` 与启动页背景与 05 规范对齐即可。

## 五、结论

- 第一期验收 = Redmi Pad Pro 上跑通 §二 清单（4、6 两项依赖前端 P0/PWA 任务）。
- 三端与迁移无需任何架构改动：加设备 = 登录同账号；换平台 = §三-⑤。
- 本文档替代 docs/01 中隐含的"多设备同步"验收口径的第一期解释：单设备交付、多端预留。
