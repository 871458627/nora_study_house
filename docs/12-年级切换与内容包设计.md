# 12 · 年级切换与内容包 — 设计方案（v1.1，取代 docs/11 的用户界面方案）

- **角色**：产品经理 + 架构师（2026-10-25）
- **性质**：设计方案，**不含实现**。用户决策原文：「不要弄得那么复杂，在家长管理页面增加一个下拉选框，可以切换小学 1-6 年级，切换后自动变更学习内容及教材，但要保留历史年级的数据不要丢失」。
- **与 docs/11 的关系**：docs/11 的「AI 教材导入生成」**不再是用户可见模块**，降级为内容生产的备选工具（见 §5）；本方案是取代它的用户界面方案。ADR-002（内容包）、ADR-003（学期归档）两个架构决策**原样沿用**，只是 key 从「导入包」换成「年级-学期」。

---

## 一、交互设计（全部改动就这两处）

### 1.1 家长设置页 → 新增「年级」下拉框

```
┌ 年级与教材 ──────────────────────────────────┐
│ 当前年级   [ 二年级 ▼ ]     学期自动：上册    │
│ 切换后学习内容与教材随之变更；                │
│ 旧年级的数据会完整封存，随时可切回查看。      │
│ [ 切换到三年级 ]                             │
└──────────────────────────────────────────────┘
```

- 下拉选项：一年级 ~ 六年级（6 项）。
- **学期自动判定**：9 月–1 月 = 上册，2 月–8 月 = 下册；家长可在下拉旁手动改为另一册（覆盖自动值，仅当前年级生效）。
- 切换 = 先选年级 → 点「切换」→ 确认弹窗：「三年级的内容将启用，二年级的进度、错题会完整封存，星星、桃粮和小桃都会带走。」
- 内容未就绪的年级：选项置灰并标注「内容整理中」（机制全年级可用，内容逐册补充，见 §4）。

### 1.2 记录页/周报页 → 「年级」选择器（历史数据入口）

- 顶部学期选择器改为年级选择器：当前年级默认展示；历史年级（如「二年级 · 上册（已封存）」）进入后只读：当年内容目录、掌握度汇总、错题本、导出该学期 JSON。
- 切回历史年级时二选一：**恢复存档**（接续当年进度错题）或**仅查看**（不动当前年级）。恢复存档属 P2，P1 先支持只读查看 + 导出。

## 二、数据与架构

### 2.1 状态模型（SyncState 增量）

```
state.grade: 1|2|3|4|5|6                 // 当前年级（缺省 2 = 兼容存量用户）
state.semesterOverride?: 's1'|'s2'       // 手动学期覆盖（缺省按日期自动）
state.activePackages[subject] = { packId, contentVersion }   // ADR-002 原样
```

内容注册表（`web/src/data/content/index.ts`）签名不变：`lessonsForSubject()` 等按 `grade+semester` 解析到对应内置包。**core/ 全部纯函数零改动**——这是方案能做到简单的根本原因。

### 2.2 内容包（ADR-002 简化形态）

- 包的组织 key = `g<年级><semester>`（如 `g2s1` = 二年级上册）；现有硬编码三科内容原样平移为 **builtin 包 `g2s1`**，随代码发布。
- 服务端新增一表（内建档案权），承载**历史年级的学习记录快照**：

```prisma
model GradeArchive {
  familyId  String @map("family_id")
  gradeKey  String @map("grade_key")   // "g2s1"
  snapshot  Json                        // lessons/mistakes/weakness/dictationQueue + 完成度摘要
  createdAt DateTime @default(now()) @map("created_at")
  @@id([familyId, gradeKey])
}
```

- 切换年级 = 服务端事务：当前年级学习切片冻结进 `GradeArchive` → `state.grade` 更新 → 新年级包激活（沿 ADR-003 语义；星星/桃粮/大餐/连续/徽章/宠物**跨年级永续**）。
- API：`PUT /api/v1/settings/grade {grade, semesterOverride?}`（走家长区鉴权）；`GET /api/v1/grade-archives`、`GET /api/v1/grade-archives/:gradeKey`（只读视图 + 导出）。

### 2.3 与既有机制的接缝

| 模块 | 改动 |
|---|---|
| `content/index.ts` | 按 gradeKey 解析内置包；未就绪年级返回占位（页面显示「内容整理中」） |
| `model.ts` | `state.grade/semesterOverride/activePackages` + normalizeState 兼容（旧数据缺省 grade=2） |
| `server` | GradeArchive 表 + 3 个路由 + activate 事务；contentVersion 迁移逻辑复用 docs/02 §5（按 gradeKey 而非包 id） |
| 计划生成/判分/周报 | **零改动**（消费注册表接口） |
| 存量数据迁移 | 现网用户无感：首次升级时把当前 lessons/mistakes 等 `builtin g2s1` 学习记录视为「二年级上册」原位保留，grade 缺省 2 |

## 三、规则细则

1. **换年级不清空任何东西**：旧行为进档案、情感资产带走（ADR-003 全套语义）。
2. **同年级学期切换**（上↔下册）：同样走归档（key 含学期），互不污染。
3. **切换不影响当日计划已完成的奖励**：奖励在切换前已入账，永远不回滚。
4. **多设备一致**：grade/semesterOverride 进 state 走既有 CAS 同步；切换需在家长区操作（PIN 保护），孩子端只读展示。

## 四、内容包生产计划（现实约束，必须向用户交底）

「切换后自动变更教材」的前提是**该年级有内容包**。内容制作是本模块的主要工作量：

| 内容包 | 状态 | 计划 |
|---|---|---|
| 二年级上册（语/数/英） | ✅ 已有（现网内容） | 平移为 builtin `g2s1` |
| 二年级下册 | 本期生产 | 与本模块同期制作（优先级最高，寒假前） |
| 一年级上/下册 | 后续版本 | 随版本逐册补充 |
| 三~六年级 | 远期 | 逐年补充；年级下拉先置灰「内容整理中」 |

**生产方式**：优先由团队按教材整理内置包（内容质量可控、家长免操作）；docs/11 的 AI 生成流水线**降级为内部生产辅助工具**（帮团队起草题目再人工校对入库），不再是家长侧功能。这样家长面保持极简（只有一个下拉框），复杂度全部留在内容生产侧。

## 六、验收口径（P1 DoD）

1. 家长区出现年级下拉（1-6），二上包现网数据平移无损。
2. 切换到有内容的年级：课本/今日计划/周报整体切换，旧年级进「历史年级」只读可导出。
3. 切换到未就绪年级：置灰不可选（或确认页明示「内容整理中」）。
4. 切回原年级（P1 用导出 JSON + 管理侧恢复验证链路，P2 上一键恢复）。
5. 星星/桃粮/宠物跨年级连续；`npm run check && npm run test && npm run build` 三连全绿。
6. **首次切换**（云端已上架）显示下载进度条且完成后内容就绪；**再次切回**同年级秒切、不触发任何下载/生成（v1.1）。
7. 切换中断后重试从断点续作，不重复已生成课程（v1.1）。
